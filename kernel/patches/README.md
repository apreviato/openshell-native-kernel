# Kernel patch series

The patches apply in name order on top of the Asterinas revision pinned in [upstream.lock.json](../config/upstream.lock.json). The build applies the series from scratch on every run and records each file's SHA-256 in `toolchain.txt`.

| Patch | Workload that requires the change | Test | Upstream status |
| --- | --- | --- | --- |
| `0001-lock-osdk-dependencies` | A reproducible kernel build. Without the lockfiles, the pinned nightly resolves `unwinding` 0.2.11 and the build fails. | The `kernel-build` check. The report's `kernel-Cargo.lock` shows the resolution used. | Not sent. A local build fix. |
| `0002-add-seccomp-filters` | Chromium's sandbox in Electron and CEF. The renderer installs seccomp-bpf filters and handles `SIGSYS`. | [seccomp.c](../../userspace/compatibility/probes/seccomp.c), the `native-seccomp` check. The same probe passes on the control Linux (`control-seccomp`). | Not sent. v0.19.0 has neither the `seccomp` syscall nor `PR_SET_SECCOMP`. |
| `0003-report-renames-to-inotify` | Node's `fs.watch`, used by hostd in Files and Memory. Without `rename` events, an atomic write never reaches the watcher. | The `fileEvents` probe of [node.mjs](../../userspace/compatibility/probes/node.mjs), the `native-compat` check. [inotify.py](../../userspace/compatibility/probes/inotify.py) reduces the case to `inotify` and `epoll`. | Not sent. v0.19.0 defines `IN_MOVED_FROM` and `IN_MOVED_TO` and never publishes them. |
| `0004-add-user-namespaces` | The namespace layer of Chromium's sandbox, created by an unprivileged process. | [namespaces.py](../../userspace/compatibility/probes/namespaces.py), the `enter` and `identity` steps. The `native-namespaces` check. | Not sent. v0.19.0 rejects `CLONE_NEWUSER` with `EINVAL`. |
| `0005-add-pid-namespaces` | Chromium's zygote isolates the renderers in a PID namespace of their own. | `namespaces.py`, the `pid` and `outside` steps. | Not sent. v0.19.0 rejects `CLONE_NEWPID`. |
| `0006-add-network-namespaces` | Renderers without access to the network or to other processes' abstract sockets, such as X11's. | `namespaces.py`, the `network` and `outside` steps. | Not sent. v0.19.0 rejects `CLONE_NEWNET` and has a single table of abstract names. |
| `0007-check-port-privileges-per-network-namespace` | hostd listens on an ephemeral loopback port as a regular user. v0.19.0 counts port 0 among the privileged ones and refuses the `listen` with `EACCES`. | [hostd-smoke.mjs](../../tools/desktop/hostd-smoke.mjs) in the guest, the `native-hostd` check. | Not sent. A bug fix. |
| `0008-give-terminals-to-their-opener` | The Desktop's Terminal opens a PTY as a regular user. The slave was created owned by root with mode 0620, and libc's `grantpt` failed. | `hostd-smoke.mjs`, the `terminal` check. | Not sent. A bug fix. |
| `0009-keep-local-pids-while-referenced` | Chromium's zygote, PID 1 of its namespace, waits for the helper that changes the root. `wait4` returned 0 because 0005 erased the local PID when reaping the child, before converting it. | [chromium-userns.c](../../userspace/compatibility/probes/chromium-userns.c), the `zygote_sandboxed` check. The `native-chromium-userns` check. | Not sent. A fix to 0005. |
| `0010-count-threads-in-task-links` | Chromium counts threads by the number of links of `/proc/self/task` and aborts with `CHECK` when the process does not look single-threaded. Every procfs directory reported 2 links. | `chromium-userns.c`, the `thread_count` check. | Not sent. v0.19.0 does not report threads in the links. |
| `0011-expose-pid-and-network-namespace-files` | Chromium only creates the namespace types whose file exists in `/proc/self/ns`. Without `pid` and `net`, the zygote was created with only the user namespace and aborted. | `chromium-userns.c`, the `namespace_files` check. | Not sent. Complements 0005 and 0006. |
| `0012-limit-unix-sockets-in-flight` | Mojo, Chromium's IPC, passes Unix sockets through `SCM_RIGHTS`. v0.19.0 only allowed that with `CAP_SYS_ADMIN` in the initial namespace, and the unprivileged renderers never received their channel. | `chromium-userns.c`, the `socket_passing` check, which also proves the limit. | Not sent. Replaces the privilege requirement with a per-user limit. |
| `0013-honor-msg-dontwait` | Chromium's network service reads the netlink address and interface dump with `recv(MSG_DONTWAIT)` until `EAGAIN`. v0.19.0 ignored the flag, the receive blocked, and the browser waited forever before creating the window. | `chromium-userns.c`, the `address_tracker` check. | Not sent. v0.19.0 only emitted a warning for the flag. |
| `0014-lay-out-environment-like-linux` | The zygote's children rewrite their title over the argument and environment strings, which must be contiguous and in order. v0.19.0 wrote the environment in reverse order, and `/proc/[pid]/cmdline` did not identify the renderers. | `chromium-userns.c`, the `process_title` check, and `cef-smoke`, which finds the renderers by that title. | Not sent. |
| `0015-inherit-address-reuse-in-accepted-connections` | The launcher restarts hostd on the same port, which the Desktop profile requires. A bug fix. |
| `0016-ignore-wake-ups-of-finished-tasks` | CEF's processes create and end many threads. A thread woken while it was finishing went back to a run queue after `exit_current` and, picked again, came out of `exit_current`: the kernel panicked with `unreachable!()` in the middle of CEF's isolation proof. | The `native-cef-isolation` check and the later phases of the `apps` action. The race is rare and has no probe of its own. | Not sent. A bug fix, related to problem 2 of [asterinas#1633](https://github.com/asterinas/asterinas/issues/1633). |
| `0017-do-not-wait-for-the-address-space-in-atomic-page-faults` | With the apps profile (Xpra, the cursor theme, `xsettingsd`), the kernel panicked when a user memory copy made with safe spinlocks page-faulted while another process held the address space: the handler waited for the `RwMutex`, and `might_sleep` brought the system down. | The `native-apps` check, which had stopped running. The race has no probe of its own. | Not sent. A bug fix. The caller that copies with safe spinlocks has not been identified yet. |
| `0018-respect-outstanding-nvme-command-ids` | Installing and using the system on a real NVMe SSD. The driver uses each command's position in the submission queue as its identifier (CID), and counted as free the positions the controller had already read, even though the command had not finished yet: a new command reused the CID of one still in progress, and one's answer went to the other. Now a position only comes back into use once its command's answer has been collected. | The NVMe case of the image test ([boot-test.sh](../../distro/image/boot-test.sh)): update, trial and confirmation with the system on an NVMe disk. | Not sent. |
| `0019-accept-evdev-output-events` | Xorg on DRM on the computer ([openshell-x.sh](../../userspace/compatibility/probes/openshell-x.sh)). X's evdev driver lights the keyboard LEDs (Caps Lock, Num Lock) by writing events to the device. v0.19.0 refused every write with `ENOSYS`, and X dropped the keyboard. Output events (LED, sound and sync) are now accepted, still without effect on the devices. Injecting input events remains unsupported. | A PS/2 keyboard under Xorg in a guest with a display (`OPENSHELL_X`), without a probe of its own. | Not sent. v0.19.0 marks writing as a TODO. |
| `0020-load-large-initrds-above-4-gib` | The live stick on a computer: the EFI stub asked the firmware for the whole initrd, contiguous, below 4 GiB, and the firmware answered `OUT_OF_RESOURCES` for the Desktop's initrd (a panic in `alloc.rs`). The stub tries below 4 GiB and, without room, accepts any address, with the high half in `ext_ramdisk_image` and `ext_ramdisk_size`, as in Linux's boot protocol. The kernel joins the two halves. Nothing reads the initrd before the linear mapping covers all physical memory. | QEMU with `max-ram-below-4g=1G` and the 1.8 GB initrd: the stub loads it at `0x352c05000`, and the kernel decompresses it and starts init. | Not sent. v0.19.0 refused an initrd above 4 GiB for the same reason as the command line, which is read early. |
| `0021-expose-the-initramfs-as-dev-initrd` | The live stick's installer. After boot, the kernel does not read the stick (there is no USB stack), and the live system is the initramfs itself. The kernel keeps it in the memory reserved at boot, and `/dev/initrd` (char 1:250, root only) reads it as it was loaded, for the installer to copy it to the disk's slot. | The installer test ([install-test.sh](../../distro/image/install-test.sh)): the installed disk boots with the copied initramfs. | Not sent. Linux has a similar `/dev/initrd` (block 1:250). |
| `0022-keep-the-efi-stub-quiet` | The loading screen, as on Live. The EFI stub wrote its progress to the firmware console over the splash GRUB drew. In release builds, the progress lines (`[EFI stub] …`) only appear with `OPENSHELL_EFI_STUB_VERBOSE` in the build; warnings and panics still go to the screen. | The installer test ([install-test.sh](../../distro/image/install-test.sh)) and the image boot: GRUB announces the slot on serial, and the kernel still reaches `initramfs is ready`. | Not sent. It is a product choice (Linux has `quiet`). |
| `0023-keep-the-boot-splash-on-the-framebuffer` | The loading screen stays up until the desktop. The kernel cleared the framebuffer when starting it, and the VT console, when activated, copied its black buffer over it. Now the framebuffer stays as GRUB left it (the splash, with `gfxpayload=keep`) and the console starts with the screen's contents; text written to the VT still appears on top. | QEMU with OVMF and screen captures: GRUB's splash stays the same after `initramfs is ready`. | Not sent. | `0024-accept-memory-locking-without-swap` | The screen lock, as on Live. Live's lock screen (inside XSecureLock) keeps the typed password only in memory locked with `mlock` and refuses to open without it. The kernel had no `mlock`, `mlock2`, `munlock`, `mlockall` or `munlockall` (ENOSYS). Since it never sends user memory to swap, every resident page stays resident: the calls check their arguments as Linux does and return success. | The lock screen opens and unlocks with the password (installed session). | Not sent. A real `mlock` (accounting by `RLIMIT_MEMLOCK`, `VM_LOCKED`) only matters with swap. |
| `0025-refresh-only-the-damaged-regions-of-the-screen` | Display performance. `DRM_IOCTL_MODE_DIRTYFB` ignored the rectangles X reports (an Asterinas TODO) and simpledrm copied the whole screen to the firmware framebuffer on every update: 8 MB per pointer movement or text cursor blink at 1920×1080. Now the DRM core passes on the changed rectangles and simpledrm copies only those; a request without rectangles still updates everything. | QEMU with OVMF: Xorg (modesetting with ShadowFB) draws the screen through the new path. | Not sent; follows the TODO in `drm_mode_dirty_fb` itself. |
| `0026-add-system-v-shared-memory` | X performance. SysV shared memory (`shmget`, `shmat`, `shmdt`, `shmctl`) was missing, and X's MIT-SHM extension did not work: Chromium, Xpra and GTK apps sent every image to X through the socket. Each segment is a VMO that every `shmat` maps shared, on the IPC structure the semaphores already use (namespaces, IDs, keys). As on Linux, `IPC_RMID` on a segment that is still attached only marks it as destroyed: it loses its key, stays attachable by ID and goes away at the last `shmdt` or unmapping. `IPC_STAT` fills `shmid64_ds`, which X uses to check the client's access; permissions follow owner, group and others; `SHM_RDONLY`, `SHM_RND`, `SHM_REMAP` and a fixed address are accepted; `SHM_LOCK` changes nothing (there is no swap). | A C test with the same results on Linux and in the guest (another process attaches and writes, a mapping inherited across fork, `IPC_STAT`, attaching after `IPC_RMID` and disappearing at the last `shmdt`, keys with `IPC_EXCL`, read-only, fixed address, access denied to another user). In the guest with Xorg, a client draws through `XShmPutImage` and X reads the colour back. | Not sent. Missing: `IPC_SET`, `IPC_INFO`/`SHM_INFO` and memory accounting in `/proc/sysvipc`. |
| `0027-map-the-whole-pc-keyboard` | A laptop's whole keyboard. The PS/2 driver only translated letters, numbers, basic punctuation, the left modifiers, Esc, F1–F12 and the arrows: right Shift, Num Lock, the keypad, Print Screen, AltGr and right Ctrl, the Super and menu keys, the volume and media keys and ABNT2's two extra keys (`<>` and `/?`) were missing. Brightness and other laptop keys arrive through ACPI, not the keyboard. |
| `0028-drive-ps2-touchpads` | A laptop's touchpad as on OpenShell Live (libinput with tap to click and natural two-finger scrolling). The PS/2 driver only spoke the mouse protocol every touchpad has: the pointer moved, but there were no two fingers and no taps. Now it looks, in the order of Linux's `psmouse`, for a Synaptics touchpad (identification, capabilities, size, resolution and clickpad) and an ELAN of versions 3 and 4 (the magic knock, the firmware and the absolute-mode registers), turns on absolute mode and reads the 6-byte packets, finding the start of the packet again after a lost byte. The gestures are libinput's defaults: one finger moves the pointer, a tap with one, two and three fingers clicks left, right and middle, two fingers scroll (natural, one axis at a time), a clickpad's bottom-right corner and a two-finger click are the right button, and a touch that starts within 0.5 s of a key (other than modifiers) neither moves nor clicks. The result is a mouse with wheels (`REL_WHEEL`, `REL_HWHEEL`), which X's evdev driver uses as it is, because there is no udev or `/sys/class/input` for libinput. The TrackPoint behind a Synaptics comes in through the pass-through packets. The kernel log says which touchpad was found and names an ALPS or an ELAN v1/v2, which stay in mouse mode; `psmouse.proto=bare`, `imps` or `exps` keeps any touchpad in it, as on Linux. | Host tests of Synaptics and ELAN v3/v4 decoding, resynchronisation, the pointer (without losing slow movement), taps, scrolling, the clickpad and typing. QEMU (a PS/2 mouse, which is not a touchpad): the probes fail, the mouse comes up as an IntelliMouse and movement, clicks and the wheel reach evdev. | Not sent. Checking on a real Synaptics and ELAN is missing. Missing: ALPS, Focaltech, ELAN v1/v2, double-tap dragging, edge scrolling and I2C-HID touchpads. |
| `0029-keep-the-kernel-log-for-dev-kmsg` | The kernel's records on a computer without a serial console. The logger only wrote to the consoles (QEMU's virtio, or nothing on a laptop), and `/dev/kmsg` did not even exist: the kernel's messages were lost, including which touchpad the driver found. Now the logger keeps the 1024 most recent records up to the notice level in a ring, whatever the console's level (`log_level` still applies to it; info is left out because it is the level of each system call's trace), and a record equal to one of the last 16 does not go in again, like printk's rate limit (the unimplemented `rseq` call every program makes). `/dev/kmsg` exists and each open file reads from the oldest record on, one per read, in Linux's format (`<level>,<seq>,<µs>,-;<text>`); after the last one, the read returns 0. Writing to it records the text as notice, without the `<level>` prefix. | `0030-drive-intel-backlights` | The brightness of the built-in screen of Intel laptops (and of the built-in screen of most NVIDIA hybrids). | `0031-add-usb-keyboards-and-mice` | USB, starting with keyboards and mice of any brand. The `aster-usb` component drives xHCI controllers (all computer USB since 2012: Intel, AMD, ASMedia, Renesas, VIA, Fresco): it takes the controller from the firmware (USB legacy support, without SMIs), routes the EHCI ports to xHCI on Intel series 7 and 8 chipsets, resets, sets up the command and event rings, the firmware's scratchpads and the DCBAA, and then, for each device plugged into a root port (at boot or later), resets the port, asks for a slot, assigns the address, fixes the control endpoint's max packet at full speed, reads the descriptors, configures and hands each interface to its class driver. | `0033-add-the-vfat-filesystem` | USB sticks and cards as they come from the factory (FAT32), the EFI partition and cameras, as on Live. `vfat` reads and writes FAT12, FAT16 and FAT32 with long names (UTF-16, case-insensitive comparison, short names with `~N` and code page 437, Windows NT's lower-case flags), creates, deletes, renames and moves files and folders, truncates and extends (what lies between the old end and the new one reads as zeros), keeps the DOS dates and maintains FAT32's FSInfo. ## 0002 · seccomp

The patch adds `seccomp(2)`, `prctl(PR_GET_SECCOMP)` and `prctl(PR_SET_SECCOMP)`, strict mode and classic BPF filters evaluated on entry to every syscall. `/proc/[pid]/status` now reports `NoNewPrivs`, `Seccomp` and `Seccomp_filters`, which the Desktop smokes read to prove the renderers are filtered.

Invariants:

- The state is per thread. New threads and processes inherit the state of whoever created them, and `execve` preserves it. Filters only accumulate: there is no operation that removes a filter.
- Installing a filter requires `no_new_privs` or `CAP_SYS_ADMIN` in the thread's user namespace.
- The validator accepts only the instructions Linux accepts for seccomp. Jumps only go forward, stay inside the program and the program ends in `RET`, so evaluation always terminates. Loads stay inside `seccomp_data`.
- Every filter in the chain runs and the most restrictive action wins.
- `SECCOMP_FILTER_FLAG_TSYNC` applies the new chain to every thread with the task set locked. `clone` copies the state again under the same lock, so a thread created during synchronisation receives the filter.
- `SECCOMP_RET_TRAP` delivers `SIGSYS` with the registers from the syscall's entry. If the signal is blocked or ignored, the process ends.

Differences from Linux:

- `SECCOMP_RET_TRACE` and `SECCOMP_RET_USER_NOTIF` fail with `ENOSYS`, as on Linux without a tracer and without a listener. `SECCOMP_FILTER_FLAG_NEW_LISTENER` returns `EINVAL`.
- `SECCOMP_RET_LOG` allows the syscall without writing to an audit log.
- `SECCOMP_GET_ACTION_AVAIL` reports only the actions actually applied.

## 0003 · rename events

`rename` publishes `IN_MOVED_FROM` in the source directory and `IN_MOVED_TO` in the destination with the same cookie, and `IN_MOVE_SELF` on the moved inode. A replaced inode receives `IN_ATTRIB` and, with no links left, `IN_DELETE_SELF`. `RENAME_EXCHANGE` reports two moves.

## 0004 · user namespaces

An unprivileged process creates a user namespace with `clone` or `unshare`, and gets every capability in it. The namespace's owner is the `euid` of its creator.

Invariants:

- The kernel keeps storing UIDs and GIDs of the initial namespace. The maps accept only one identity range (`N N count`), so an ID visible in the namespace is the same ID outside it. An ID outside the range is not mapped.
- Each map is written once, by a thread of the namespace or of the parent. Without privilege in the parent, the thread only maps its own `euid` and only maps its own `egid` after writing `deny` to `setgroups`. Mapping other IDs requires `CAP_SETUID` or `CAP_SETGID` in the parent.
- The capability check follows Linux's `cap_capable`: the thread uses its effective capabilities in its own namespace, the owner of a child namespace has all of them in it, and capabilities apply in descendants. Outside that, none.
- `CAP_DAC_OVERRIDE`, `CAP_SETFCAP`, set-user-ID and set-group-ID only apply to inodes whose owner and group are mapped in the thread's namespace. `setuid`, `setgid`, `setgroups` and their variants refuse unmapped IDs.
- Creating a filesystem instance still requires `CAP_SYS_ADMIN` in the initial namespace, because the kernel does not yet separate the types that are safe for a user namespace.

## 0005 · PID namespaces

Each process and each thread has a global ID, the ID in the initial namespace, and a local ID in its namespace and in each ancestor. Local IDs exist only at the syscall boundary: the kernel converts the ID received by `getpid`, `kill`, `wait4`, `waitid`, `tgkill`, `setpgid`, `getpgid`, `getsid`, `prlimit64`, priorities, affinity, timers, `pidfd_open`, `capget`, `capset`, `fcntl(F_SETOWN)`, `clone` with `CLONE_PARENT_SETTID`, `set_tid_address`, robust futexes, job control ioctls, `siginfo` and `SCM_CREDENTIALS`.

Invariants:

- The PID table hides from a thread the entries of namespaces that do not descend from its own. A forgotten conversion therefore does not reach an outside process.
- A namespace's first process has PID 1, adopts the namespace's orphans, and its exit kills the other processes and prevents new ones from entering.
- `unshare(CLONE_NEWPID)` changes the namespace of the next children and can only be used once per process.

Differences from Linux:

- `/proc` lists the visible processes' global IDs, and `ptrace` receives global IDs. The PID table still prevents access to outside processes. Chromium's sandbox removes `/proc` from the renderers' view before using them.

## 0006 · network namespaces

A network namespace has its own interfaces, route tables and abstract Unix socket names. The initial one uses the interfaces found at boot. A new one starts with only its own loopback, so its processes reach neither the network nor other namespaces.

Differences from Linux:

- The socket uses the namespace of the thread operating it, not that of its creator. The two only differ if a socket is passed to a process in another network namespace.
- A new namespace's loopback gets the next global interface index, not index 1.
- The thread serving the loopback stays alive after the namespace's last process ends.

## 0007 and 0008 · fixes

Port 0 asks for an ephemeral port and does not require `CAP_NET_BIND_SERVICE`. Ports 1 to 1023 require the capability in the user namespace that owns the network namespace. A PTY's slave belongs to the `fsuid` and `fsgid` of whoever opened `/dev/ptmx`, as on Linux.

## 0009 to 0011 · what Chromium checks

- A process's local ID belongs to the `Process` and a secondary thread's to the `PosixThread`. It stays valid as long as the object exists, and a reaped process still has the PID `wait4` reports. Global IDs are not reused, so a local ID is not confused with a new process's.
- `/proc/[pid]/task` reports 2 links plus one per thread, like Linux's `proc_task_getattr`. The other procfs directories keep 2.
- `/proc/[pid]/ns` lists `pid`, `pid_for_children` and `net`, besides the types v0.19.0 already had.

## 0012 · Unix sockets in flight

A Unix socket sent inside a cycle, for example through its own channel, stays alive after the last descriptor is closed. Linux collects these cycles. Asterinas does not have a collector yet, and v0.19.0 avoided the problem by requiring `CAP_SYS_ADMIN`, which prevents the IPC of any ordinary multi-process application.

The patch charges the Unix sockets of each `SCM_RIGHTS` message to the sender's real UID and limits the total in flight to the sender's `RLIMIT_NOFILE`, like Linux's `too_many_unix_fds`. Above the limit, the send fails with `ETOOMANYREFS`, unless the sender has `CAP_SYS_RESOURCE` or `CAP_SYS_ADMIN`. The charge is released when the recipient receives the descriptors or when the message is discarded.

The risk that remains open: a deliberate cycle keeps up to `RLIMIT_NOFILE` of a user's sockets alive until shutdown. The limit prevents a user from exhausting the kernel's memory that way, but does not reclaim those sockets. The cycle collector is future work.

## 0013 and 0014 · sockets and process titles

- `MSG_DONTWAIT` makes a single send or receive call non-blocking on IP, Unix, netlink and vsock sockets, whatever the file's mode. `MSG_NOSIGNAL` is now listed as supported: the kernel never sends `SIGPIPE` on sockets.
- The environment strings come right after the argument strings and in ascending order, as on Linux. `/proc/[pid]/cmdline` follows `get_mm_cmdline`: if the last byte of the argument area is not NUL, the title continues into the environment area up to the first NUL.

## 0015 · server restarts

As on Linux, an accepted connection inherits `SO_REUSEADDR` from the listener at the time of `accept`. A server restarted with `SO_REUSEADDR` can `bind` the port again while the previous one's connections finish closing. The series does not change the case of two sockets in `listen` on the same port: as in v0.19.0, it stays allowed when every socket on the port uses `SO_REUSEADDR`. Linux refuses that case.

## 0016 · task exit

`Waker::wake_up` marks the task as woken and only then puts it on a queue. In that interval, the task can continue without sleeping to the end of its function, and `exit_current` takes it off the queue and clears its CPU. The queue then received a finished task, and the scheduler went back to it. The patch marks the task as finished when its function returns, in `kernel_task_entry`, and the scheduler's `enqueue` refuses the marked task after getting its CPU. The mark does not use `Thread::is_exited`, because POSIX exit can still sleep after marking the thread, while closing files and ending the process.

## 0017 · page faults in atomic mode

A copy from or to a process's memory can page-fault. ostd then calls the kernel's handler, which reads the address space under an `RwMutex`. With safe spinlocks (atomic mode), waiting is forbidden: if another process held the mutex, the wait called `might_sleep`, and the kernel panicked (`This function might break atomic mode`). When free, the mutex is taken without waiting, and the fault is handled as usual. The patch exposes ostd's `in_atomic_mode` and, in atomic mode, takes the address space only if it is free (`try_read`); when it is busy, the copy fails and the system call reports the error. A first version refused every fault in atomic mode and broke the guest, because those accesses are common and almost always find the mutex free. The caller that copies with safe spinlocks still has to be identified and fixed.

## Diagnosing Chromium failures

Official Chromium and CEF builds trigger `int3` on a `CHECK` without writing out the condition, and emit almost no logs. The problems in this series were located with temporary kernel instrumentation, which is not part of the patches:

- On the fault signal, record the RIP and the file mapping containing it. The offset resolved against the SDK's `libcef.so`, which keeps its symbols, points to the `CHECK`.
- For syscalls that block for more than 0.7 s on the main thread of CEF processes, record the number, arguments, return value and the chain of frame pointers of the user stack. Chromium is built with frame pointers, so the stack resolves down to the waiting function.
- Record process exits with a non-zero status and the thread names at `exit_group`, which identify Chromium's process type.

With `LOG_LEVEL=warn`, the kernel also reports unimplemented syscalls and the signals that end processes. Comparing with the same CEF host on the builder's Linux separates what belongs to the kernel from what belongs to the environment.

## Validating the namespaces

The probe prepares, still in the initial namespace, a root-owned file with mode 0600, an abstract socket and a process. Then, unprivileged, it enters the new namespaces and requires that the file, the socket and the process are inaccessible, that `setuid(0)` and a second write of `uid_map` fail and that a namespace cannot be created after the capabilities are dropped. The same probe passes on the control Linux.
